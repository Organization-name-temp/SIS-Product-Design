# Solo design workflow

Use 20 hours as a weekly planning allowance. It is an estimate, not a fixed deadline.
Adham chooses priorities and approves design. The assistant prepares artifacts and verification evidence.

## First-week foundation sequence

This sequence preserves the requested starting workflow. Completed foundation work does not need repetition.

| Session | Allowance | Adham does | Assistant prepares | Exit evidence |
|---|---|---|---|---|
| 1. Working agreement | 3 hours | Choose scope, review times, ownership, and the next user outcome. | Agreement draft, source inventory, questions, and decision record. | One reviewable agreement with unresolved questions. |
| 2. Foundation contract | 5 hours | Select brand, type, language, density, geometry, and behavior. | Token options, comparisons, naming rules, and examples. | Approved contract and explicit proposals. |
| 3. Foundation examples | 5 hours | Inspect values in context and request corrections. | Interactive specimens, responsive layouts, and state examples. | A working foundation reference. |
| 4. Representative flow | 4 hours | Select a real requirement and review the task sequence. | A flow map, wireframes, component reuse, and missing-state list. | One bounded design packet draft. |
| 5. Review and queue | 3 hours | Review quality and select the next slice. | Findings, corrections, evidence, and updated backlog. | Accepted work or explicit open findings. |

The current foundation work covers much of sessions 2 and 3.
Complete personal visual acceptance before another broad foundation expansion.
Use the next representative flow only after its real requirements are clear.

## Working agreement

Record the next user outcome, its source requirements, its boundary, and its review date.
Keep one active design slice. Keep one prepared next slice.
Ask developers for implementation constraints and evidence when a real integration needs them.
Developer consultation does not introduce another design approver.
Do not wait for every SIS screen before a reviewed slice moves to implementation.

## Design packet

Each packet contains the actor, permission scope, flow, screens, states, tokens, responsive behavior, and acceptance criteria.
Link the requirement and Jira issue. Label assumptions and sample rules.
Define focus, errors, pending feedback, empty results, denial, retry, and partial outcomes where applicable.
Record design approval and implementation verification separately.

## Weekly capacity

Reserve time for source review, design, verification, and corrections.
Reduce scope when hours fall below 20. Do not remove accessibility or error behavior to meet a screen count.
Use additional hours for evidence, corrections, and the next flow outline.
The assistant can draft, implement local demonstrations, inspect sources, run checks, and keep the project record.
Adham supplies priorities, user access, and final visual judgment.
